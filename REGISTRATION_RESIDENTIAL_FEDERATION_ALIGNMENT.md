# Registration & Residential Federation Alignment

## Scope

Bundle D aligns registration, profiles, public pages, dashboards, guidance,
accessibility, archive, readiness, and signals for Client, Provider, and
Center language.

It does not create UI, widgets, screens, Firebase writes, Firestore
collections, runtime validation, approval flows, registration logic,
automation, or notifications.

## Client Doctrine

Client Federation is based on:

- identity
- visibility
- accessibility
- sovereignty
- support

It does not define clients as cases.

## Residential Doctrine

Residential Federation is based on:

- family support
- recovery support
- accessibility support
- personal signals

It is not a session doctrine.

## Registration Alignment

Registration fields are classified as:

- private_only
- public_visible
- dashboard_visible
- review_only
- signal_source
- guidance_source

## Field Parity

Every field should map clearly across:

- Registration
- Profile
- Public Page
- Dashboard

## Profile Alignment

Provider, Center, and Client registration profiles have parity models that
connect declared fields to public and dashboard usage.

## Accessibility

Supported accessibility modes:

- standard
- easy_reading
- audio_assisted
- visual_assisted

## Guidance

Guidance alignment prepares:

- Easy Reading
- Screen Reader
- Audio Labels
- Learn More

## Archive

Registration and profile archive alignment is reference-only and does not
archive runtime data in this wave.

## Readiness

Readiness alignment connects registration, profiles, residential doctrine, and
roadmap markers.
