# Archive Retention Policy V1

Result: ARCHIVE_RETENTION_POLICY_DEFINED

## Retention Classes

| Retention Class | Meaning | Examples |
| --- | --- | --- |
| PERMANENT | Must never be deleted. | Prompt memory, archive cards, forensic audit, Admin Zero evidence, constitutional freeze. |
| LONG_TERM | Preserve unless superseded by Owner-approved archive consolidation. | Execution wave reports, release candidate reports, identity migration reports. |
| EDUCATIONAL | Preserve as lessons and signals. | Engineering lessons, educational signals, human journey gaps. |
| SOURCE_EVIDENCE | Preserve as proof of origin, not active runtime. | Clean Core references, old identity evidence, legacy workspace mappings. |
| FUTURE_DELETE_CANDIDATE | May be deleted later only after archive card and Owner approval. | Duplicate checkpoints, redundant interim reports, obsolete placeholders. |

## Future Deletion Candidate Policy

Deletion may only happen if all are true:

1. The item has no unique historical value.
2. The item is represented by an archive card or final report.
3. Lessons have been extracted.
4. Owner approves deletion explicitly.
5. Git history remains intact.
