# MASTER_CARD_RUNTIME_SYSTEM_V1

Prompt Asset: PROMPT_ASSET_068
Status: REGISTERED

## Purpose

Define the complete Generation 1 card runtime lifecycle model.

Cards are governance entities. Runtime consumes them.

## Critical Doctrine

- Cards describe.
- Runtime executes.
- Cards are governance.
- Runtime is operation.
- Registries define.
- Runtime consumes.

## Card Definition

A card is a governed description of an approved object, route, asset, signal, screen, tool, collection, policy, ownership record, package, or runtime behavior boundary.

A card is not executable code.

## Card Lifecycle

```text
Card Creation
-> Card Registration
-> Card Validation
-> Card Ownership Assignment
-> Card Distribution
-> Runtime Consumption
-> Replacement / Freeze / Archive / Clone / Recreation / Retirement
```

## Runtime Boundary

Runtime may read and consume approved card definitions. Runtime may not invent unregistered card authority.

## Constitutional Rule

No runtime feature may claim card authority unless the card exists, is registered, has ownership, and has validation status.
