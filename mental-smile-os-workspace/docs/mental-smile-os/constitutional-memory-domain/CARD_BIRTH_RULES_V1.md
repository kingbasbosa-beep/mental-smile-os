# Card Birth Rules V1

Status: ACTIVE_MEMORY_RULES
Domain: Constitutional Memory Domain
Applies to: constitutional card assets

## 1. Foundational Rule

Every card must be traceable. No card may exist as a constitutional object without:

- Birth Prompt.
- Birth Signal.
- Birth Authority.
- Birth Lineage.
- Parent Guide.
- Registry Entry.
- Validation Status.

## 2. Birth Sequence

```text
Prompt
-> Birth Authority
-> Parent Guide
-> Card Asset
-> Card Registry Entry
-> Memory Lineage
-> Memory Validation
```

## 3. Required Card Birth Evidence

Every card birth must preserve:

- Who created this.
- Why it was created.
- Which prompt created it.
- Which signal authorized it.
- Which guide contains it.
- Which registry tracks it.

## 4. Forbidden Birth Outcomes

The following are constitutionally invalid:

- Orphan Card.
- Card Without Parent Guide.
- Card Without Birth Prompt.
- Card Without Registry Entry.
- Card Without Lineage.
- Card With Unknown Birth Authority.
- Card With No Validation Status.

## 5. Memory Integration

Every created card must automatically preserve inside Constitutional Memory Domain:

- Birth Prompt.
- Birth Signal.
- Birth Authority.
- Birth Justification.
- Birth Lineage.

## 6. Boundary

Card birth rules define traceability only. They do not create domains, authorize expansion, or grant governance authority.
