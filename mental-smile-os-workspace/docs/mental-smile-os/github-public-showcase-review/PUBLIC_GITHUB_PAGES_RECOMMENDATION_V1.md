# PUBLIC_GITHUB_PAGES_RECOMMENDATION_V1

## Purpose

Recommend public GitHub Pages / repository entry structure.

## Best Public Entry Page

Use root `README.md` as the first public landing page.

Reason:

GitHub visitors land on the repository README first, not deep documentation folders.

## Best Public Documentation Package

Use:

```text
mental-smile-os-workspace/docs/mental-smile-os/generation-1-showcase/
```

as the main human-readable documentation package.

## GitHub Pages Recommendation

Recommended:

```text
Use the showcase folder as GitHub Pages source content after adding a simple index/landing page.
```

Do not use the full `docs/mental-smile-os/` tree as the first public Pages experience because it contains dense constitutional and execution records that are useful, but too heavy for first-time visitors.

## Recommended Public Navigation

1. Root README
2. Generation 1 Showcase
3. Release Candidate V1
4. Runtime Signal-Routing Bootstrap
5. Constitutional Freeze for deeper reviewers

## Public Readiness Decision

```text
PUBLIC_READY_WITH_WARNINGS
```

## Required Before Public Sharing

Replace root README with a short public landing README.

No code, Firebase, deployment, or credential changes are required for documentation public readiness.
