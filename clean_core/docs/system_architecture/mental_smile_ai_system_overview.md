# Mental Smile AI System Overview

## Status

Draft architecture documentation. Runtime AI is not enabled. Cloud Functions are deferred.

## Purpose

The Mental Smile AI architecture foundation prepares for future safety-reviewed AI support while preserving a deny-by-default and backend-governed design. Current work is contracts, copy, and boundaries only.

## Current Foundation Layers

1. Legal consent foundation: consent types, versions, immutable-oriented records, and disclaimer text.
2. AI governance placeholders: collection names, safe fields, event/incident/trace/policy snapshot placeholders, disabled runtime config.
3. AI safety core skeleton: identity boundaries, risk levels, response modes, placeholder filters, injection guard, validator, policy engine, fail-safe contracts.
4. Crisis-safe UX copy: calm Arabic-first support copy, grounding prompts, trusted-person guidance, emergency limitation text.
5. Backend boundaries: trusted operation contracts, protected fields, booking lifecycle boundary, escalation boundary, AI governance boundary.

## What Is Not Enabled

- No runtime AI.
- No OpenAI/Gemini integration.
- No AI chat.
- No crisis automation.
- No emergency dispatch.
- No Cloud Functions orchestration.
- No notification runtime.
- No admin safety dashboard.

## Safety Principles

- Security over convenience.
- Calm support over authority.
- Human support direction in crisis.
- No diagnosis or treatment claims.
- No emergency guarantees.
- No raw sensitive persistence by default.
- Client cannot control governance, payment, escalation, or AI moderation states.

## Future Readiness

Future AI phases should require legal review, platform review, backend-governed execution, emulator tests, audit trails, policy snapshot enforcement, and explicit user-facing disclosures before runtime enablement.
