# Clean Core Import Contamination Candidates

Draft candidate list for manual import review. No command scan or code rewrite was performed.

## Must Clean Before Export

| Category | Risk | Why It Blocks Export |
| --- | --- | --- |
| Parent-path imports | Extraction blocker | Extracted package cannot rely on files outside its boundary. |
| `../lib` imports | Extraction blocker | Indicates dependency on old source project paths. |
| Legacy package imports | Extraction blocker | Future package identity will break these imports. |
| Firebase options imports in core contracts | Extraction blocker | Reusable contracts should not own app Firebase setup. |
| Generated localization imports in core contracts | Extraction blocker | Generated app localization should remain app-owned. |
| Router imports in core contracts | Extraction blocker | Package contracts should not depend on app navigation. |
| Generated config/plugin imports | Extraction blocker | Generated app files are not stable package API. |

## App-Owned Dependency Candidates

| Category | Risk | Suggested Ownership |
| --- | --- | --- |
| Flutter UI pages | App-owned dependency | Keep in host app until UI package strategy exists. |
| Firestore feature flows | App-owned dependency | Keep app-owned or wrap behind backend/data boundary. |
| Firebase Auth state | App-owned dependency | Keep in app shell/auth boundary. |
| Asset references | App-owned dependency | Keep app-owned until package asset manifest exists. |
| Platform-specific setup | App-owned dependency | Keep in Android/iOS/web app roots. |
| Route constants and app navigation | App-owned dependency | Keep app-owned until route adapter is defined. |

## Needs Review

| Category | Risk | Review Question |
| --- | --- | --- |
| Test imports | Medium | Do they require app shell, live Firebase, or emulator startup? |
| Feature repositories/services | Medium | Do they import Firebase directly or app-level providers? |
| Generated file references | Medium | Are they regenerated by app tooling only? |
| Localization imports | Medium | Are strings app-owned or package-owned? |
| Environment/config imports | Medium | Do they assume a local/staging/production app config? |

## Likely Safe

| Category | Reason |
| --- | --- |
| Pure enum/model contracts | No runtime or app-shell dependency when imports are sibling-only. |
| Governance placeholder contracts | Designed as backend-governed, fail-closed, runtime-disabled foundations. |
| Documentation | Not compiled into runtime. |
| Markdown test plans | Offline planning artifacts only. |

## Manual Review Checklist

- Search for imports containing `../`.
- Search for imports containing `../lib`.
- Search for imports containing the current app package name.
- Search for imports of Firebase packages inside reusable `lib/core/*` contracts.
- Search for Flutter imports inside pure core contracts.
- Search for generated localization and Firebase options imports.
- Search for router, route, navigation, and asset-generated imports.
- Search tests for app shell, emulator, Firebase project, and generated config assumptions.

## Explicit Non-Action

This document identifies likely contamination categories only. No extraction, cleanup, import rewrite, deletion, or package restructuring was performed.
