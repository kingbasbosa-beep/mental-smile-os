# PART A: Constitutional Construction Principles

## A1. Reality First

```text
Build what is needed now.
Prepare for what is needed later.
```

Mental Smile must distinguish between current operating reality and future constitutional capacity. A function may be named before it is staffed. A boundary may be documented before it is enforced. A future department may be delegated before it becomes operational.

Reality first means the institution grows from actual capacity, not imagined maturity.

## A2. No Governance Fantasy

Mental Smile must not activate governance structures that do not exist.

Forbidden pattern:

```text
Create a room
without people,
without process,
without memory,
without authority boundaries.
```

Governance fantasy creates false confidence and operational debt.

## A3. Delegation Before Department

Functions may exist before departments exist.

During construction:

```text
missing department
-> delegated function
-> reviewed responsibility
-> mature department later
```

Delegation is temporary and scoped.

```text
Delegation != Authority Transfer
```

## A4. Continuity Before Expansion

Operational continuity has priority over growth.

The institution must preserve:

- current operations
- codebase continuity
- documentation continuity
- backup continuity
- governance memory
- owner/development working capacity

Expansion is unhealthy if it increases fragility.

## A5. Enforcement Follows Maturity

Governance enforcement must evolve gradually:

```text
Documentation
-> Warning
-> Soft Validation
-> Hard Validation
```

Never:

```text
Documentation
-> Permission Denied
```

Hard enforcement before operational maturity causes paralysis, bypasses, and distrust.

## A6. Authority Must Not Outrun Memory

No high-risk authority should activate before memory can preserve:

- actor
- reason
- evidence
- scope
- decision
- correction
- review

Core law:

```text
No Sovereign Authority Without Sovereign Memory.
```

# PART E: Permission Denied Prevention Program

## E1. Level 0: Documentation

Purpose:

- define doctrine
- name risk
- classify authority
- create checklists

Activation requirement:

- none beyond agreement.

Runtime behavior:

- no blocking.

## E2. Level 1: Warnings

Purpose:

- surface risk without blocking.
- identify drift.
- educate operators.

Activation requirement:

- documented rule
- visible warning
- safe fallback

Runtime behavior:

- action continues.

## E3. Level 2: Soft Validation

Purpose:

- validate expected conditions.
- record issues.
- allow override with reason.

Activation requirement:

- owner-approved policy
- operator understanding
- review path
- no critical dependency on validation

Runtime behavior:

- warns, requires acknowledgement, or records exception.

## E4. Level 3: Governed Execution

Purpose:

- actions follow approved process.
- audit/review exists.

Activation requirement:

- department/function exists at Level 3 maturity
- audit path exists
- appeal/correction path exists
- fallback exists

Runtime behavior:

- actions route through governed process.

## E5. Level 4: Hard Enforcement

Purpose:

- prevent forbidden actions.

Activation requirement:

- mature governance unit
- protected memory
- command boundary
- clear owner/department authority
- rollback/correction path
- operational fallback
- tested edge cases

Runtime behavior:

- blocks forbidden action.

Hard enforcement must be rare before the institution matures.
