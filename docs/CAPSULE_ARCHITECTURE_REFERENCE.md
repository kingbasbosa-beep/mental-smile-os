# CAPSULE ARCHITECTURE REFERENCE

## Purpose

A Capsule is a governed package of Mental Smile product capability. It can be
cloned, themed, localized, deployed, backed up, or extended while inheriting
central doctrine.

## Capsule Definition

A capsule contains a bounded product experience:

- code;
- assets;
- localization;
- signals;
- cards;
- reports;
- prompts;
- documentation;
- backups;
- theme definitions;
- monitoring expectations.

A capsule is not a fork of the federation constitution.

## Centralized Doctrine

The following remain centralized:

- constitutional restrictions;
- term card meanings;
- forbidden language;
- signal doctrine;
- card doctrine;
- asset lifecycle rules;
- readiness doctrine;
- safety boundaries;
- AI generation rules;
- owner ratification;
- registry versioning.

## Cloneable Units

| Unit | Cloneable? | Condition |
|---|---|---|
| Code | Yes | Must retain doctrine boundaries |
| Assets | Yes | Must keep registry ownership and licensing |
| Localization | Yes | Must preserve meaning parity |
| Signals | Yes | Must preserve source and consent boundaries |
| Cards | Yes | Must keep card IDs or mapped derivatives |
| Reports | Yes | Must identify capsule scope |
| Prompts | Yes | Must include AI language and doctrine rules |
| Documentation | Yes | Must cite source registry versions |
| Backups | Yes | Must preserve constitutional state |

## Capsule Manifest

A capsule manifest should declare:

- capsule ID;
- purpose;
- audience;
- owner registry;
- source registry versions;
- card IDs;
- asset IDs;
- term IDs;
- signal IDs;
- routes or destinations;
- localization scope;
- theme compatibility;
- forbidden doctrine;
- monitoring requirements;
- backup strategy;
- release status.

## Inheritance Model

```text
Central Constitution
-> Registry Versions
-> Capsule Manifest
-> Capsule Card Set
-> Capsule Asset Set
-> Capsule Language Set
-> Capsule Signal Set
-> Capsule Experience
-> Capsule Report
-> Capsule Backup
```

## Capsule Lifecycle

```text
Concept
-> Registry Admission
-> Card Coverage
-> Asset and Language Readiness
-> Signal Mapping
-> Build Readiness
-> Release
-> Monitoring
-> Revision
-> Archive or Dormancy
```

## Capsule Restrictions

A capsule may not:

- restore booking ownership;
- create approval authority;
- assign people or providers;
- own recovery;
- bypass language governance;
- bypass asset ownership;
- invent signals without registry destination;
- use AI to create doctrine;
- hide runtime behind historical archive.
