# FEDERATION TOPOLOGY REFERENCE

## Purpose

This reference summarizes the Mental Smile Federation product topology. It has
no runtime effect.

## Layer Stack

```text
Constitution Layer
Registry Layer
Signal Layer
Card Layer
Asset Layer
Language Layer
Room Layer
District Layer
Capsule Layer
AI Layer
Monitoring Layer
Owner Layer
```

## Layer Responsibilities

| Layer | Responsibility | Cannot Do |
|---|---|---|
| Constitution | Define doctrine and boundaries | Run operations |
| Registry | Own terms, assets, signals, cards, domains | Become scattered feature memory |
| Signal | Express interests, states, readiness, safety, and preferences | Diagnose or grant authority |
| Card | Give active objects identity and build eligibility | Legitimize contaminated legacy |
| Asset | Govern visual ownership and lifecycle | Grow uncontrolled folders |
| Language | Govern meaning, vocabulary, parity, and generation | Translate forbidden doctrine |
| Room | Provide role or person spaces | Own journeys or cases |
| District | Organize city domains | Force lifecycle ownership |
| Capsule | Package governed product units | Fork doctrine |
| AI | Compose, validate, classify, and assist | Legislate meaning |
| Monitoring | Observe signals, drift, readiness, and safety | Approve, assign, or control |
| Owner | Ratify strategy and doctrine | Run daily operations |

## Core Flow

```text
Constitution defines what may exist.
Registries define what each thing means.
Signals express living state and intent.
Cards declare product identity.
Assets and language express the product.
Rooms and districts organize experience.
AI assists within boundaries.
Monitoring observes.
Owner ratifies strategic evolution.
```

## Product Rule

No active product element should exist without:

- a constitutional purpose;
- a registry owner;
- a signal relationship when relevant;
- a card when active;
- governed language;
- governed assets when visual;
- a route or consumer if runtime;
- a retirement path if legacy.

## Relationship Map

| Source | Feeds | Meaning |
|---|---|---|
| Constitution | Registries | Admits or forbids concepts |
| Registries | Cards | Gives product objects governed identity |
| Registries | Language | Defines legal vocabulary |
| Registries | Assets | Defines ownership and lifecycle |
| Signals | Readiness | Completeness creates visibility state |
| Signals | Recommendations | Fingerprints attract resources |
| Cards | Rooms and districts | Product objects become visible surfaces |
| Rooms | Signals | People and roles express intent |
| Districts | Discovery | Public and shared ecosystem navigation |
| Monitoring | Owner | Evidence and risk move upward |
| Owner | Registries | Strategic ratification moves downward |

## No-Return Boundaries

- No booking runtime.
- No approval authority.
- No assignment authority.
- No admin control room.
- No operational archive runtime.
- No platform-owned recovery.
- No unregistered language doctrine.
- No orphan assets.
- No cardless active runtime.
