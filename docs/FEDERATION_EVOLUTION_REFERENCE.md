# FEDERATION EVOLUTION REFERENCE

## Purpose

This reference defines the natural product evolution path for Mental Smile
Federation when all current constitutions are respected.

## Evolution Path

```text
Clean Application
-> Governed Runtime
-> Carded Product System
-> Signal-Aware City
-> Room and District Federation
-> AI-Assisted Governance
-> Capsule Factory
```

## Stage 1: Clean Application

Purpose: remove extinct doctrine and stabilize active runtime.

Primary work:

- eliminate booking, approval, assignment, archive, and control-room residue;
- keep safety;
- prove active constitutional purpose.

Exit condition:

- no active runtime exists only for extinct doctrine.

## Stage 2: Governed Runtime

Purpose: every active element declares its role.

Primary work:

- card active runtime;
- map signals;
- map language;
- map assets;
- verify Firestore collections and routes;
- classify remaining blockers.

Exit condition:

- every active element has a constitutional destination.

## Stage 3: Carded Product System

Purpose: cards become build passports.

Primary work:

- system cards;
- signal cards;
- tool cards;
- content cards;
- resource cards;
- provider and center category cards;
- safety cards;
- magnet cards;
- aspiration and pathway cards.

Exit condition:

- no active product object is cardless.

## Stage 4: Signal-Aware City

Purpose: Mental Smile City becomes meaningful through signals.

Primary work:

- signal producers;
- signal consumers;
- readiness;
- magnet matching;
- resource fingerprints;
- provider and center discovery signals;
- personal space signal boards.

Exit condition:

- signals drive readiness, discovery, recommendations, and monitoring.

## Stage 5: Room and District Federation

Purpose: rooms and districts become product architecture.

Primary work:

- client room;
- provider room;
- center room;
- monitoring room;
- owner room;
- city districts;
- district cards;
- district assets;
- district language.

Exit condition:

- rooms and districts can evolve independently while sharing doctrine.

## Stage 6: AI-Assisted Governance

Purpose: AI helps generate, validate, classify, and prepare product material.

Primary work:

- asset assistant;
- localization assistant;
- theme assistant;
- signal assistant;
- archive assistant;
- recommendation assistant;
- factory prompts.

Exit condition:

- AI outputs carry registry evidence and cannot bypass doctrine.

## Stage 7: Capsule Factory

Purpose: Mental Smile can create governed product capsules.

Primary work:

- capsule manifest;
- registry inheritance;
- asset bundles;
- language bundles;
- signal bundles;
- card bundles;
- backup and report bundles.

Exit condition:

- new products can be born from the constitution instead of ad hoc feature work.

## Constant Principles

- Person-led recovery.
- Signals before authority.
- Readiness before visibility.
- Cards before build.
- Registries before scale.
- Language parity.
- Asset ownership.
- Monitoring as observation.
- AI as constrained assistant.
- Owner ratification for doctrine.

## Strategic Answer

The natural evolution path is to complete registry coverage, card every active
product object, ground signals into real destinations, govern assets and
language, make rooms and districts signal-aware, introduce constrained AI
assistants, and then package Mental Smile as a capsule-ready federation factory.
