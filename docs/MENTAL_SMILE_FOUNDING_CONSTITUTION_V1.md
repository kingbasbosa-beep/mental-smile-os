# Mental Smile Founding Constitution v1

Status: Founding constitutional document  
Authority level: Highest architectural governance reference  
Runtime effect: None  
Scope: All future governance, architecture, execution, migration, partnership, data, AI, finance, legal, and operational authority

---

## Preamble

Mental Smile began as an operational Flutter/Firebase platform with admin-centered control. Through Grounding Waves, Extraction Waves, Sovereign Waves, and constitutional exploration, the project discovered that a platform handling mental-health-adjacent operations, payments, sessions, support, trust, finance, legal evidence, and human continuity cannot be governed as a cockpit.

It must be governed as a constitutional operational federation.

This Constitution exists to prevent the return of hidden authority, super-admin control, silent mutation, erased memory, financial/legal ambiguity, tenant overexposure, AI overreach, and dehumanized operations.

Core founding law:

```text
Authority may operate.
It may not become absolute.
```

# PART A: Constitutional Reality

## A1. Current Runtime Reality

Mental Smile currently exists as:

- Flutter application runtime
- Firebase/Firestore operational storage
- route-gated UI access
- custom-claim/role-based authority assumptions
- `/admin/*` compatibility cockpit
- Firestore operational truth
- passive shadow command wrappers in selected booking and chat flows
- no active constitutional command runtime
- no immutable sovereign audit runtime
- no true room separation
- no real Owner/Control/Sovereign execution boundary yet

The current runtime is stable enough to preserve, but not pure enough to expand as-is.

## A2. Admin Reality

The current admin surface is overloaded. It contains:

- observation
- analysis
- approval
- direct mutation
- finance residue
- legal/compliance-adjacent residue
- trust authority
- support/continuity operations
- AI policy governance
- system/domain authority
- marketing/content workspace authority
- frozen legacy aliases

Constitutional finding:

```text
/admin/* is compatibility history.
It is not the future constitutional architecture.
```

## A3. Data Reality

Not all data has the same constitutional status.

Mental Smile contains:

- user-private local context
- platform operational truth
- sovereign financial/legal truth
- protected memory
- cached client projections
- future audit evidence

Device-only storage is valid for private personal data. It is not valid for multi-party operational truth, payment evidence, consent evidence, dispute evidence, trust approval, payout/accounting, or audit memory.

## A4. Authority Reality

Current authority is still partially broad, admin-centric, and residue-driven. Future authority must become:

```text
scoped
reviewable
auditable
room-bounded
human-supervised
backend-executed where high-risk
protected by memory
```

# PART B: Constitutional Vision

## B1. Constitutional Federation

Mental Smile shall evolve into a governed operational federation composed of distinct rooms, domains, pipelines, and memory layers.

The federation shall include:

- Owner Room
- Control Room / Admin Operations
- Sovereign Finance
- Sovereign Legal
- App Operations
- Web Operations
- Tenant/Center Operations
- Clinician Operations
- Client Self-Service
- Trusted Backend/System Authority
- Protected Memory / Audit Authority
- AI recommendation systems under governance

## B2. Constitutional Authority Hierarchy

The authority hierarchy shall be:

```text
Constitution
 -> Protected Memory / Audit
 -> Registry / Policy Legitimacy
 -> Owner Governance
 -> Sovereign Finance / Sovereign Legal
 -> Trusted Backend / Command Execution
 -> Control Room Observation and Escalation
 -> Operational Domains
 -> Client / Clinician / Center / Tenant scoped action
 -> AI recommendation only
```

No layer may silently bypass the layers above it.

## B3. Leadership and Governance

Leadership exists to steward the Constitution, not to override it.

The Owner or leadership body may:

- ratify policy
- prioritize development
- govern entity strategy
- approve high-risk constitutional decisions
- supervise room boundaries
- ratify registry/pipeline legitimacy
- resolve cross-room governance conflict

The Owner or leadership body may not:

- become super-admin
- silently mutate runtime truth
- erase audit memory
- unilaterally execute finance/legal finality
- bypass sovereign review
- override human rights, consent, or protected memory

## B4. Departmental Governance

Departments shall be treated as scoped authority environments, not personal empires.

Each department must define:

- purpose
- visibility boundary
- mutation boundary
- data boundary
- escalation path
- audit obligation
- forbidden authority

## B5. Human and AI Review

AI may recommend, summarize, classify, and assist. AI may not govern.

Human review remains required for:

- finance finality
- legal risk
- consent-sensitive continuity
- dispute resolution
- trust approval/blocking
- high-risk rollback/correction
- emergency authority
- constitutional change

AI doctrine:

```text
AI may advise.
Humans must supervise.
The Constitution must govern.
```

# PART C: Constitutional Transition Blueprint

## C1. Transition Principle

Mental Smile shall not be rewritten destructively.

The transition shall proceed by:

```text
inventory
freeze
label
shadow
audit
wrap
separate
enforce selectively
```

Never by:

```text
panic rewrite
route rename theater
admin resurrection
backend dictatorship
sovereign cockpit creation
audit-less enforcement
```

## C2. Extraction Doctrine

All overloaded admin authority shall be extracted by meaning before UI movement.

Extraction order:

1. Authority ownership
2. Data ownership and protected memory
3. Room boundary specification
4. Route extraction
5. Command/audit/backend enforcement

Routes shall not be renamed before authority changes are understood.

## C3. Control Room Transition

Control Room shall emerge from admin only after purification.

Control Room may:

- observe
- analyze
- raise cases
- track queues
- monitor anomalies
- view command status
- forward finance/legal/support/system concerns

Control Room may not:

- own finance truth
- own legal truth
- confirm payouts
- finalize accounting
- mutate high-risk lifecycle truth directly
- govern AI policy
- own system infrastructure
- become super-admin

## C4. Owner Room Transition

Owner Room shall be created only after admin residue and sovereign boundaries are mapped.

Owner Room shall govern:

- strategy
- constitutional policy
- registry/pipeline legitimacy
- development priorities
- IT/infrastructure direction
- AI governance
- high-risk ratification
- partnership governance
- quarterly governance review

Owner Room shall not be daily operations.

## C5. Sovereign Transition

Sovereign Finance and Sovereign Legal shall remain conceptual until protected memory, audit boundaries, and command boundaries exist.

No sovereign room may be born as a new cockpit.

## C6. Protected Memory Transition

Protected memory must precede sovereign execution.

Audit shall evolve from scattered logs toward:

- append-only memory
- correction history
- redaction governance
- retention governance
- dispute evidence
- finance/legal defensibility
- consent history
- command lifecycle memory

## C7. Quarterly Governance Review

Mental Smile shall conduct periodic governance review at least quarterly.

Quarterly review shall cover:

- admin residue
- frozen legacy status
- finance/legal boundaries
- protected memory readiness
- AI governance
- data ownership risks
- tenant/center/clinician/client boundary health
- human safety and continuity risks
- authority drift
- audit gaps
- route extraction progress
- partnership and sharing governance

# PART E: Foundational Doctrines

## E1. Owner Ratification Doctrine

Owner ratification is required for:

- constitutional change
- high-risk policy change
- registry legitimacy changes
- AI policy boundaries
- broad pipeline/valve legitimacy
- platform partnership governance
- high-risk finance/legal policy impacts
- emergency authority review

Owner ratification is not required for routine scoped operations that have approved policy and safe boundaries.

## E2. Recommendation Doctrine

Rooms and departments may recommend actions. Recommendation is not execution.

Control Room recommendations shall be routed to:

- Owner for governance decisions
- Sovereign Finance for finance truth
- Sovereign Legal for legal truth
- App/Web/Tenant Operations for scoped operational matters
- Backend/System for technical execution

## E3. Protected Memory Doctrine

Audit is protected memory.

Protected memory must preserve:

- actor
- authority
- reason
- target
- prior state
- requested state
- result
- correction history
- redaction history
- retention logic
- dispute and consent evidence where required

Protected memory may be redacted by governed process. It must not be silently deleted.

## E4. Data Ownership Doctrine

Data shall be classified into:

| Layer | Meaning |
| ----- | ------- |
| User-Owned Local Data | Private context, notes, preferences, drafts. |
| Platform Operational Truth | Multi-party workflows and active runtime state. |
| Sovereign Protected Memory | Finance, legal, consent, dispute, audit, archive, correction truth. |
| Cached Client Views | Convenience projections, not source truth. |
| User Export/Portability | User-accessible copies of permitted records. |

## E5. Partnership Governance Doctrine

Partnerships, sharing arrangements, white-label relationships, enterprise federation, and tenant extensions must obey:

- tenant isolation
- data boundary protection
- no hidden authority transfer
- audit visibility by scope
- finance/legal sovereignty
- user dignity
- no AI/governance bypass

## E6. Human Review Doctrine

Human review is mandatory where automated decision could affect:

- payment
- payout
- legal evidence
- trust/blocking
- consent-sensitive outreach
- disputes
- emergency restriction
- life-impacting support paths

## E7. Transition Doctrine

Compatibility may remain.

Expansion must be governed.

Legacy may be frozen.

Burial requires verification.

No destructive rewrite shall be treated as constitutional progress.

# PART G: Constitutional Compliance Checklist

Any future execution must answer:

## G1. Authority

- Who is requesting the action?
- What authority do they hold?
- Is authority distinct from visibility?
- Is mutation required?
- Is this action sovereign, operational, owner-governed, or support-scoped?
- Could this recreate super-admin?

## G2. Room Boundary

- Which room/domain owns the decision?
- Which room may only observe?
- Which room executes?
- Which room audits or reviews?
- Is Control being given mutation it should not hold?
- Is Owner being used as a universal override?

## G3. Data Ownership

- Is this personal local data?
- Is this platform operational truth?
- Is this sovereign protected memory?
- Can this safely be device-only?
- Does this affect another party's rights?
- Is cached data being mistaken for truth?

## G4. Memory

- Must this action be remembered?
- Is audit required before enforcement?
- Can correction be additive?
- Is deletion forbidden?
- Does this require retention/redaction policy?
- Is consent/dispute/payment/legal evidence involved?

## G5. Finance / Legal

- Does this affect payment, payout, accounting, settlement, refund, archive, tax, legal hold, dispute, or consent evidence?
- If yes, why is it not sovereign?
- Is Control only observing?
- Is Owner only ratifying policy?
- Is sovereign memory defined?

## G6. AI

- Is AI recommending or deciding?
- Is human review required?
- Is AI output auditable?
- Could AI manipulate emotion, consent, dependency, or authority?

## G7. Transition Safety

- Is this a rewrite disguised as cleanup?
- Does this alter production behavior?
- Does this expand legacy admin?
- Does this need freezer labeling?
- Can rollback happen without rewriting memory?
- Is the smallest safe step being taken?

## G8. Quarterly Review

Each quarterly governance review must verify:

- no hidden admin expansion
- no sovereign authority without memory
- no Owner super-admin drift
- no Control mutation creep
- no AI governance creep
- no protected memory erosion
- no tenant/partner data leakage
- no unresolved frozen debt without status
- no route rename without authority change
- no humane continuity violations
