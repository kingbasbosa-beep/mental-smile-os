# Accessibility Organization Directory Card V1

Status: ACTIVE_GOVERNANCE_CARD
Classification: ACCESSIBILITY_ORGANIZATION_DIRECTORY_FOUNDATION
Phase: 7B
Runtime effect: none

## Purpose

Define the future accessibility organization directory structure before implementation.

The directory is a future access resource, not a verification claim.

## Future Registry Structure

Future organization entries should be governed by a registry before runtime use.

Initial proposed fields:

| Field | Meaning | Governance Note |
| --- | --- | --- |
| Organization | Public organization name. | Must not imply endorsement without verification. |
| Category | Resource category or access domain. | Must use governed category values. |
| Country | Country of operation or primary service. | Needed for relevance and jurisdiction context. |
| Website | Public website URL. | Must be reviewed for safety and accuracy. |
| Email | Public contact email. | Must avoid exposing private personal emails. |
| WhatsApp | Public WhatsApp or contact number if available. | Must be optional and governed. |

## Organization

Organization names should be official public names where possible.

Aliases may be stored only if a future registry allows them.

## Category

Categories should describe access resource type, not user identity.

Examples:

- communication support
- learning resources
- assistive technology
- community support
- advocacy
- family support

## Country

Country helps users find geographically relevant resources.

Country does not imply legal approval, licensing, or clinical authority.

## Website

Website links must be treated as external exits and should follow future link safety rules.

## Email

Email should be an official public contact when possible.

## WhatsApp

WhatsApp should be optional and clearly treated as a contact method, not a booking or emergency pathway.

## Boundary

This card does not create a collection, seed data, directory UI, verification process, or external link implementation.
